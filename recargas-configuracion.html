Recargas y confirmaciones

Una billetera general. Cada solicitud tiene un REC permanente. Un correo, una captura o un QR personal no prueban por sí mismos la recepción ni la identidad del pagador.

Estado de esta integración: recargas manuales y revisión administrativa; conexión OAuth preparada. Las acreditaciones automáticas personales de Lemon y Binance permanecen deshabilitadas hasta disponer de autorización, confirmación oficial y una referencia inequívoca por solicitud.

Recarga manual

  1. En Mi billetera, selecciona Recargar → Manual y crea tu solicitud REC.
  2. Coordina con ADMIN el medio receptor autorizado antes de enviar dinero. Lemon solo aparece habilitado cuando su autorización está configurada. No se asume equivalencia entre USDT y soles.
  3. Después de depositar, abre «Enviar comprobante por WhatsApp» y adjunta el comprobante. El mensaje incluye tu REC e importe; abrir WhatsApp no significa que se haya enviado o aprobado.
  4. ADMIN coteja el ingreso real y su referencia única en Control de recargas. El saldo solo cambia al registrarse la acreditación.

Conectar correo de ADMIN

Solo ADMIN puede conectar y consultar avisos de depósitos. Las conexiones de proveedores de STREAM BULL’S conservan permisos separados. Actualmente el titular debe crear o configurar las aplicaciones OAuth; no se solicitan contraseñas.

  1. En Google Cloud configura el consentimiento OAuth y un cliente web con Gmail API habilitada. En Microsoft Entra registra una aplicación web para las cuentas que utilizarás. Puedes reutilizar las mismas aplicaciones de la integración de entregas, agregando estos callbacks exactos.
  2. Google:
    https://pqalxtrcyrpmwqdlibqd.supabase.co/functions/v1/cc-recharge-mail/oauth/google
    Microsoft:
    https://pqalxtrcyrpmwqdlibqd.supabase.co/functions/v1/cc-recharge-mail/oauth/microsoft
  3. Configura en los secretos de Supabase Edge Functions CC_RECHARGE_GOOGLE_CLIENT_ID, CC_RECHARGE_GOOGLE_CLIENT_SECRET, CC_RECHARGE_MICROSOFT_CLIENT_ID y CC_RECHARGE_MICROSOFT_CLIENT_SECRET. También se admiten las credenciales CC_STREAM_* ya existentes. Nunca las publiques en el navegador ni en GitHub.
  4. Permisos: Google openid email gmail.readonly; Microsoft openid email offline_access User.Read Mail.Read. Estos permisos permiten leer el buzón: el filtro por remitente es una restricción de la aplicación, no del consentimiento OAuth. Se recomienda un buzón dedicado. Las políticas del proveedor pueden exigir verificación de la aplicación.
  5. En Mi perfil → Correos de confirmación de depósitos, autoriza el correo desde Google o Microsoft y guarda los remitentes exactos de las notificaciones oficiales.
  6. Pulsa Revisar avisos. Se consultan páginas limitadas del Inbox y se guardan datos mínimos para revisión, no el contenido íntegro ni adjuntos. Los avisos repetidos no se duplican ni acreditan dinero.

La lectura real queda pendiente de configurar las aplicaciones y autorizar un buzón. Falta validar los formatos con mensajes reales autorizados. Esta versión permite revisión de correo a petición de ADMIN; no incluye un sondeo programado activo. Desconectar elimina los tokens locales y solicita revocación cuando el proveedor lo admite; también puedes revocar el consentimiento desde Google o Microsoft.

Qué permite una recarga automática

Se conserva la integración Binance Merchant: firma de notificación, reconsulta oficial del pedido, comprobación del importe, moneda, comercio y transacción, y acreditación atómica con referencia única. Requiere una cuenta Merchant aprobada, credenciales válidas y habilitación explícita del servidor. El QR de una cuenta personal no activa esta integración.

El historial personal de Binance Pay dispone de una API oficial, pero consultar movimientos no demuestra que un depósito corresponda a un REC. No se conecta ni se asigna por importe/hora sin un mecanismo autorizado de vinculación. Para Lemon se ha verificado documentación de recepción por QR; no se ha verificado una API pública de conciliación para esta cuenta personal.

Los depósitos sin identificación permanecen pendientes. No se habilitan redes cripto, activos ni conversiones no configurados. En Merchant se conserva el límite vigente del servidor y su importe PEN/USDT confirmado; nunca se supone que 1 USDT equivale a S/1.
